# CCTV Storage Calculator

Бесплатный калькулятор объёма видеоархива CCTV/NVR. React, TypeScript strict, Vite, Tailwind CSS. Расчёты в браузере: без сервера, телеметрии и внешних runtime-сервисов.

## Реализовано в MVP

- Независимые группы камер: количество, средний битрейт, H.264/H.265, 720p, 1080p, 4MP, 4K или свои размеры.
- Запись 24/7 или ежедневный интервал для каждой группы, включая переход через полночь.
- Мгновенный расчёт объёма в GB, TB, GiB, TiB, расхода за сутки и вклада каждой группы.
- Обратный расчёт срока хранения по доступной ёмкости HDD.
- Валидация, нулевой поток с явным состоянием «Без ограничения», сброс к исходным параметрам.
- Русский адаптивный интерфейс, светлая/тёмная/системная темы, нативные поля с подписями и сообщениями об ошибках.

Оформление выбирается в шапке и сохраняется в браузере. Системный режим следует `prefers-color-scheme`; выбор применяется до загрузки приложения. Если браузер запрещает localStorage, оформление работает до закрытия страницы. Тема не меняет параметры расчёта. Поддерживаются уменьшенное движение, клавиатура, увеличение текста до 200% и короткие объявления результата для скринридера.

Начальные параметры и новые группы: **4 камеры, 4 Mbps на камеру, H.265, 1080p, 24/7**. Общие параметры: **30 дней, диск 8 TB**. Результат по умолчанию: **5.184 TB**. Для интервального режима исходное время — **08:00–20:00**. Битрейт является примером, а не гарантией расхода конкретной камеры.

## Формулы, единицы и допущения

```text
groupBytes = cameraCount × bitrateBitsPerSecond × recordingSeconds / 8
totalBytes = сумма groupBytes
retentionDays = availableBytes / totalBytesPerDay
```

| Единица | Значение |
| --- | --- |
| Mbps | 1 000 000 бит/с |
| GB | 1 000 000 000 байт |
| TB | 1 000 000 000 000 байт |
| GiB | 2^30 байт |
| TiB | 2^40 байт |

Битрейт — определяющий ввод. Кодек и разрешение являются метаданными и не меняют битрейт. FPS не включён. Модель предполагает постоянный средний битрейт, без коэффициентов сжатия и надбавок.

Сутки — ровно **86 400 секунд**. Ввод времени с точностью до минуты, длительность вычисляется в секундах. Интервал повторяется ежедневно; конец раньше начала означает переход через полночь. Равные начало и конец недопустимы: используйте 24/7. Это модель фиксированной длительности, без часовых поясов, DST и исторического календаря.

Обратный расчёт использует эффективный суточный расход и возвращает среднюю длительность в сутках, а не дату заполнения с учётом времени старта. При нулевом потоке срок «Без ограничения», в том числе при ёмкости 0. При положительном потоке и нулевой ёмкости срок 0.

Служебные данные, аудио, файловая система, RAID, резерв NVR и практические потери ёмкости не учитываются. Вводите доступную для видео ёмкость.

### Числовая стратегия и пределы

- 1–100 групп, в каждой 0–10 000 целых камер.
- Битрейт: 0–1000 Mbps, до 3 знаков после запятой. Принимаются точка и запятая.
- Размеры: 1–16 384 целых пикселей; срок: 1–3650 целых суток; ёмкость: 0–1000 выбранных единиц.
- Ноль камер или битрейта означает отсутствие потока. Пустые, отрицательные и нечисловые значения отклоняются.

Используется JavaScript `number`, любой суточный/итоговый объём ограничен **Number.MAX_SAFE_INTEGER = 9 007 199 254 740 991 байтом** (около 9 PB). Сочетание допустимых параметров может превысить общий предел и будет отклонено. Битрейт переводится в целые бит/с с шагом 1000; при минутных интервалах объёмы целочисленны. Промежуточного округления объёмов нет. Преобразования единиц и срок используют двойную точность; округляется только отображение (объём до 3 знаков, срок до 2).

Целые объёмы записи в поддерживаемом диапазоне проверяются точно по независимому эталону `bigint`, включая ближайшие достижимые значения к пределу. Дробная ёмкость HDD вводится как `number`: её десятичное представление, преобразование в байты и обратный срок хранения могут иметь погрешность двойной точности. Гарантия точного целого объёма записи не означает точного представления произвольной дробной ёмкости.

### Контрольные примеры за 30 дней

| Камеры | Mbps на камеру | Часов в сутки | Байты | Результат |
| --- | --- | --- | --- | --- |
| 1 | 1 | 24 | 324 000 000 000 | 324 GB |
| 4 | 1 | 24 | 1 296 000 000 000 | 1.296 TB |
| 8 | 4 | 24 | 10 368 000 000 000 | 10.368 TB |
| 1 | 8 | 12 | 1 296 000 000 000 | 1.296 TB |

Одна камера 1 Mbps с записью 24/7: 1 TB хватает на **92.5925925926 суток**.

Положительный объём или срок ниже точности отображения показывается как «< 0,001» или «< 0,01», чтобы не смешивать его с нулём.

## Установка и разработка

Требуются **Node.js 24.x** и npm. Версия Node указана в `.nvmrc`; зависимости фиксируются `package-lock.json`.

```sh
npm ci
npm run dev
```

Адрес разработки обычно `http://127.0.0.1:5173/cctv-storage-calculator/`. Используйте путь, указанный Vite.

## Проверки и production-сборка

```sh
npm ci
npm run typecheck
npm run lint
npm run test
npm run build
npx playwright install chromium
npm run test:e2e
git status
git diff --check
```

Vitest работает без watch: чистая математика и React Testing Library. Playwright проверяет production-сборку через preview на порту 4173 в Chromium: desktop и эмуляция viewport Pixel 7, с перехватом неожиданных pageerror. Это не тест физического Android-устройства. На Linux браузеру могут понадобиться зависимости: `npx playwright install --with-deps chromium` (так работает CI).

Браузерные проверки также контролируют console errors, неудачные запросы и HTTP-ошибки ресурсов. Responsive-сценарии охватывают 320, 360, 375, 390, 430, 768, 1024, 1440 и 1920 px. Axe проверяет WCAG A/AA в обеих темах и состояниях формы; автоматический аудит не заменяет проверку со скринридером. Скриншоты сохраняются для просмотра, без нестабильных межплатформенных PNG-goldens. Наблюдения загрузки, LCP/CLS и ввода с 1/100 группами прикладываются к HTML-отчёту; это не Lighthouse-баллы и не гарантии производительности.

CI сохраняет HTML-отчёт и скриншоты в артефакт `browser-qa` на 7 дней, в том числе при падении E2E. Для последовательных локальных замеров используйте `npm run test:e2e -- --workers=1`.

Для проверки опубликованного сайта можно задать `PLAYWRIGHT_BASE_URL`; тогда локальный preview не запускается. `PLAYWRIGHT_OUTPUT_DIR` меняет каталог артефактов, например на `.qa/production`. Тесты тем требуют публикации версии, поддерживающей темы. Без этих переменных проверяется исключительно локальная production-сборка.

Чтобы хранить браузер внутри проекта, перед установкой и E2E задайте в PowerShell:

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD\.playwright"
npx playwright install chromium
npm run test:e2e
```

`npm run build` создаёт `dist/`. `npm run preview` запускает просмотр этой сборки по пути `/cctv-storage-calculator/`. Выходные файлы, браузер и отчёты исключены из Git.

Результаты проверки MVP и замечания о среде: [VERIFICATION.md](VERIFICATION.md).

## Архитектура

- `src/domain/storage/`: чистые модели, расписания, единицы, общий pipeline расчёта и его тесты.
- `src/features/calculator/`: черновик формы, исходные значения, разбор ввода и ошибки.
- `src/app/`: страница и компонентные тесты.
- `src/components/calculator/`, `src/components/ui/`: редактор группы и поля ввода.
- `src/lib/ru.ts`: тексты интерфейса для будущей локализации.
- `src/styles/`: Tailwind и стили; `tests/e2e/`: Playwright.

Общий `calculate` обслуживает итог, вклад групп и обратный расчёт. Ошибочный черновик не поступает в расчёт; старые результаты скрываются до исправления.

## CI и GitHub Pages

`ci.yml` запускается для PR в main и как переиспользуемый workflow. Выполняет Node 24, npm ci, typecheck, lint, тесты, build, установку Chromium и E2E с правами чтения содержимого.

`pages.yml` запускается **только на push в main**: полный переиспользуемый CI → загрузка проверенного dist → deploy. Повторного полного CI и повторной сборки того же коммита нет. Артефакт загружается только после всех проверок и только для push в main; PR не публикует Pages. Права pages:write и id-token:write выдаются только deploy; публикации сериализованы. Vite base: `/cctv-storage-calculator/`.

Владелец должен:

1. Выбрать **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. Проверить PR, дождаться CI и самостоятельно объединить его в main.
3. Проверить успешный workflow GitHub Pages и открыть опубликованный сайт.

Для обязательного review и запрета обхода CI настройте защиту main: workflow не запрещает прямой push владельца. Настройки репозитория автоматически не изменяются.

Целевой адрес: [sxwxrslvvt.github.io/cctv-storage-calculator](https://sxwxrslvvt.github.io/cctv-storage-calculator/). Указание адреса **не подтверждает успешную публикацию**.

## Ограничения и планы

Конфигурация только в памяти страницы и теряется при перезагрузке; сохраняется только выбор оформления. Только русский интерфейс. Нет расписаний по дням недели, прогнозирования VBR/движения, RAID, каталога HDD, сравнения сценариев, экспорта, ссылок на конфигурацию, сохранения проектов, сервера и аккаунтов.

Возможные следующие этапы: английская локализация, сохранение/передача конфигурации, сложные расписания. Они **не реализованы** в MVP.
